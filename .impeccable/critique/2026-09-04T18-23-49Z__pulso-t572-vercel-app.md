## Design Specificity Verdict

**LLM assessment**: Not a generic SaaS panel with the labels swapped — the evidence is in the code, not just the palette. `FicharBoton.tsx`'s `marcar()` resolves geolocation with a silent fallback so a GPS failure never blocks a clock-in; `VerificarRostroModal.tsx` is explicitly built to auto-close and retry for gloved/wet hands; `/admin/presencia` triages a shift into Avisos → Sin fichar → rostro dudoso → jornada terminada, which is how a real shift-lead's morning actually unfolds — not a generic activity feed. It loses points on the desktop admin surfaces: Empleados rows and the Arqueos list fall back to flat, form-like density that could belong to any internal tool.

**Deterministic scan**: `detect.mjs` run against `app/admin`, `app/fichar`, `components` found **1 finding, exit code 2**: `gray-on-color` at `app/admin/turnos/TurnosClient.tsx:453` (`text-slate-400` flagged against `bg-red-100`). **False positive** — verified by reading the file: the gray text is the *resting* state on a neutral chip background; `bg-red-100` only appears together with `hover:text-red-600`, both hover-scoped. The detector paired a base-state text color with a hover-state background without correlating the `hover:` prefixes, so the two classes never actually co-occur.

**Visual overlays**: not available for this run. The browser-injection overlay is served from a local HTTP script server (`live-server.mjs`), and the deployed app is HTTPS — browsers block that as mixed content (`net::ERR_BLOCKED_BY_CLIENT`), confirmed identically on two separate pages before Assessment B stopped rather than repeat the same systemic failure five times. No console-reported per-element overlay exists for this run; the CLI scan above is the only deterministic evidence.

## Overall Impression

The mobile clock-in flow (`/fichar`) is the strongest thing in the app — a big forgiving button, calm failure states, a "never blocks" architecture that's actually implemented, not just claimed. The desktop admin side is functionally solid but visually flatter than it needs to be: several screens show every control for every row at once instead of the collapse-then-expand pattern the app already uses elsewhere (branches on Empleados, tabs on Ajustes). The single biggest opportunity: an unconfirmed close on the cash-reconciliation modal can silently drop a financial record with no trace — worth fixing before it fixes itself via a real discrepancy nobody can explain later.

## What's Working

1. **The "never blocks" principle is real, not a slogan** — `obtenerUbicacion()` resolves `null` on any GPS failure, `VerificarRostroModal` is code-commented "Nunca bloquea," and both degrade to a flagged-for-review state instead of an error wall.
2. **Presencia's operational triage** (Avisos → Sin fichar → rostro sin verificar → jornada terminada) reads as built by someone who has run a real shift, not a generic dashboard template.
3. **Biometric consent copy** in `RegistrarRostro.tsx` — explicit checkbox, plain-language purpose limitation, stated right to deletion — real privacy-by-design, not boilerplate.

## Priority Issues

**[P1] Arqueo (cash count) can be skipped silently.** `ArqueoModal`'s close (X) button discards the modal with no confirmation and no record — a shift can close with cash uncounted and nothing flags it on `/admin/arqueos`.
Why it matters: the entire point of the arqueo feature is catching cash discrepancies; a silent skip defeats it, and by the time someone notices, the Fudo "esperado" data may no longer be queryable for that window.
Fix: require an explicit "Omitir arqueo" action distinct from the X, and leave a visible "Sin arquear" row on the Arqueos list rather than nothing at all.
Suggested command: `/impeccable harden`

**[P1] Empleados rows show every control for every employee at once.** Role dropdown, category dropdown, "Regenerar passkey," "Poner contraseña," and Precio/hora are all always visible per row — no click-to-expand, even though the branch level one step up already uses exactly that collapse pattern (shipped this session).
Why it matters: with 8-12 staff per branch this is a wall of controls competing for attention on every scan of the list — the opposite of the collapse pattern the app just adopted one level up.
Fix: collapse each row to name + status badges, expand on click, mirroring the branch-collapse behavior.
Suggested command: `/impeccable layout`

**[P2] Currency has no thousands separator.** The Fudo "Ventas y mozos" panel shows raw numbers like `$7531447.00`.
Why it matters: at a glance this reads as an ambiguous string of digits, not a peso amount — exactly where scanability matters most (it's real revenue).
Fix: format with `toLocaleString('es-AR', { style: 'currency', currency: 'ARS' })` or at minimum a thousands separator.
Suggested command: `/impeccable clarify`

**[P2] Arqueo "Diferencia" badge doesn't distinguish overage from shortage.** Flat amber regardless of sign.
Why it matters: an encargado scanning the Arqueos list can't tell "fine, rounding" from "investigate, cash is missing" without reading the number.
Fix: split the badge tone — rose/red for a shortage (contado < esperado), a calmer tone for overage.
Suggested command: `/impeccable clarify`

**[P3] Export buttons on Reportes are visually undifferentiated.** Excel/PDF/CSV render at identical weight with no default emphasized.
Fix: low priority — give the most-used format (likely Excel, given it now carries the daily-detail sheet) primary styling, the others ghost.
Suggested command: `/impeccable polish`

*Note: Assessment A also flagged the Semana Gantt view for having no hour axis under the demand curve — that was fixed and deployed independently during this same session (the peak badge now tracks the curve's real height and hour marks run underneath), so it's already resolved and not listed above as open.*

## Persona Red Flags

**Riley (Stress Tester)**: ArqueoModal's unconfirmed X-close is exactly the "wrong fast tap" edge case that fails silently and has real financial consequences — no error, no trace, just a missing record.

**Casey (Distracted Mobile User)**: `/fichar`'s single giant button is a strong pass for this persona — forgiving, thumb-sized, never blocks. The only friction is the first-run biometric-consent modal requiring a full read before the button unlocks, which is appropriate given what it's consenting to, not a flaw.
